<objective>
## Goal
Créer des hardlinks dans downloads/ après transfert vers storage/ pour maintenir le seeding BitTorrent, et filtrer ces hardlinks lors du scan pour éviter les doublons.

## Purpose
Permet aux fichiers transférés de rester visibles par les trackers BitTorrent avec leur nom original, sans duplication d'espace disque (même inode). Le fichier physique réside dans storage/, le hardlink temporaire dans downloads/.

## Output
- Table SQLite `hardlinks` pour le registre des hardlinks créés
- Config `hardlink_retention_days` pour la durée de rétention
- Hardlinks créés automatiquement lors de chaque transfert (CLI et web)
- Scanner ignorant les fichiers avec nlink > 1
</objective>

<acceptance_criteria>

## AC-1: Hardlink créé après transfert
```gherkin
Given un fichier downloads/Films/Movie.2024.x264.mkv transféré vers storage/Films/Drame/.../Film (2024).mkv
When le transfert réussit via transfer_file()
Then un hardlink existe à downloads/Films/Movie.2024.x264.mkv avec le même inode que le fichier storage
And une entrée HardlinkModel est créée en DB avec download_path, storage_path, created_at, expires_at
```

## AC-2: Fallback gracieux si hardlink impossible
```gherkin
Given un transfert entre deux filesystems différents (cross-device)
When os.link() lève OSError
Then le transfert réussit quand même (le move est déjà fait)
And un warning est loggé
And aucune entrée HardlinkModel n'est créée
```

## AC-3: Scanner ignore les hardlinks
```gherkin
Given un fichier dans downloads/ qui est un hardlink (st_nlink > 1)
When le scanner parcourt downloads/
Then ce fichier est ignoré et n'apparaît pas dans les résultats de scan
```
