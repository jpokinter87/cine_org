<objective>
## Goal
Mettre en place le déploiement production de CineOrg : service systemd pour le serveur web, script de déploiement git dev→serveur, et documentation complète.

## Purpose
Permettre de faire tourner CineOrg comme un service système permanent sur le serveur, avec un workflow simple pour pousser les mises à jour depuis la machine de dev.

## Output
- Fichier service systemd (`deploy/cineorg.service`)
- Script de déploiement (`deploy/deploy.sh`)
- Documentation déploiement (`deploy/README-deploy.md`)
- Commande CLI `serve` adaptée pour la production (workers, logs)
</objective>

<acceptance_criteria>

## AC-1: Service systemd fonctionnel
```gherkin
Given le fichier cineorg.service installé dans /etc/systemd/system/
When on exécute systemctl start cineorg
Then le serveur web démarre sur le port 8000
And les logs sont écrits dans le fichier configuré
And le service redémarre automatiquement en cas de crash
```

## AC-2: Script de déploiement dev→serveur
```gherkin
Given des changements commités sur la machine de dev
When on exécute deploy.sh depuis la machine de dev (ou le serveur)
Then git pull récupère les derniers changements
And uv sync met à jour les dépendances
And le service systemd est redémarré
And le script affiche le statut du service après redémarrage
```

## AC-3: Commande serve adaptée production
```gherkin
Given la commande cineorg serve
When on la lance avec --workers N
Then uvicorn démarre avec N workers
And le mode reload est désactivé par défaut (production)
And les logs uvicorn passent par loguru
```

<task type="auto">
  <name>Task 1: Créer le fichier service systemd et le script de déploiement</name>
  <files>deploy/cineorg.service, deploy/deploy.sh</files>
  <action>
    Créer le répertoire `deploy/` à la racine du projet.

    **cineorg.service :**
    - Type=simple, User/Group configurables (commentaires)
    - WorkingDirectory vers le répertoire du projet
    - ExecStart avec `uv run cineorg serve --host 0.0.0.0 --port 8000`
    - EnvironmentFile pointant vers le .env du projet
    - Restart=on-failure avec RestartSec=5
    - After=network.target
    - Section [Install] WantedBy=multi-user.target
    - Commentaires expliquant l'installation : `sudo cp deploy/cineorg.service /etc/systemd/system/ && sudo systemctl daemon-reload && sudo systemctl enable cineorg`

    **deploy.sh :**
    - Script bash avec set -euo pipefail
    - Variables configurables en haut (PROJECT_DIR, SERVICE_NAME)
    - Étapes : cd projet → git pull → uv sync → systemctl restart → systemctl status
    - Afficher un résumé (commit actuel, statut service)
    - Utilisable depuis le serveur directement
    - chmod +x
  </action>
  <verify>
    - Le fichier .service est un fichier systemd valide (vérifier syntaxe)
    - Le script deploy.sh est exécutable et contient les étapes attendues
    - `bash -n deploy/deploy.sh` ne retourne pas d'erreur de syntaxe
  </verify>
  <done>AC-1 et AC-2 satisfaits : service systemd et script de déploiement créés</done>
</task>

<task type="auto">
  <name>Task 2: Adapter la commande serve pour la production</name>
  <files>src/main.py</files>
  <action>
    Modifier la commande `serve` dans src/main.py :
    - Ajouter option `--workers` (int, default=1) pour le nombre de workers uvicorn
    - Quand workers > 1, utiliser uvicorn avec le paramètre `workers`
    - Le mode `--reload` reste disponible mais désactivé par défaut
    - S'assurer que les logs uvicorn passent toujours par loguru (déjà le cas)
    - Ajouter option `--access-log / --no-access-log` (default: True) pour les logs d'accès

    Ne PAS changer le comportement par défaut existant (host 0.0.0.0, port 8000).
    Ne PAS ajouter de reverse proxy nginx — CineOrg est usage personnel, uvicorn direct suffit.
  </action>
  <verify>
    - `uv run cineorg serve --help` montre les nouvelles options (--workers, --access-log)
    - `uv run cineorg serve --workers 2` démarre sans erreur (tester brièvement, Ctrl+C)
    - Les tests existants passent toujours
  </verify>
  <done>AC-3 satisfait : commande serve supporte workers et options production</done>
</task>
