<task type="auto">
  <name>Task 1: Corriger positionnement popover lecteur et supprimer option Migré</name>
  <files>src/web/static/css/style.css, src/web/templates/library/_play_btn.html, src/player_profiles.py</files>
  <action>
    **1. Popover positionnement (CSS)**

    Dans `style.css`, le popover `.play-profile-popover` est positionné avec `bottom: calc(100% + 6px)` (au-dessus du bouton). Quand le bouton est proche du haut de page, le popover est coupé.

    Modifier le CSS pour :
    - Garder la position par défaut au-dessus (`bottom: calc(100% + 6px)`)
    - Mais pour les cas proches du haut de page, utiliser une classe CSS `popover-below` qui inverse la position :
      ```css
      .play-wrapper.popover-below .play-profile-popover {
          bottom: auto;
          top: calc(100% + 6px);
      }
      .play-wrapper.popover-below .play-profile-popover::after {
          bottom: auto;
          top: -6px;
          border-top: none;
          border-bottom: 6px solid var(--bg-card);
      }
      ```
    - Ajouter un petit script JS dans `_play_btn.html` qui détecte si le popover déborderait du viewport et ajoute/retire la classe `popover-below` :
      ```js
      // Lors du toggle, vérifier si le popover tiendrait au-dessus
      const rect = wrapper.getBoundingClientRect();
      const popoverHeight = popover.offsetHeight || 120;
      if (rect.top < popoverHeight + 10) {
          wrapper.classList.add('popover-below');
      } else {
          wrapper.classList.remove('popover-below');
      }
      ```

    **2. Supprimer option "Migré" (player_profiles.py)**

    Dans `player_profiles.py` :
    - Modifier `load_profiles()` (lignes 68-91) : supprimer l'appel à `_migrate_from_env()` et le code de migration (lignes 78-90)
    - Supprimer la fonction `_migrate_from_env()` entièrement
    - Au chargement, filtrer les profils existants pour retirer tout profil nommé "Migré" :
      ```python
      data["profiles"] = [p for p in data["profiles"] if p.get("name") != "Migré"]
      ```
    - Si le profil actif était "Migré", basculer vers "Local"
  </action>

    - `uv run pytest tests/unit/test_player.py -x -q`

  </verify>

<task type="auto">
  <name>Task 2: Bouton réinitialisation workflow + logs serveur avec horodatage</name>
  <files>src/web/routes/workflow.py, src/web/templates/workflow/index.html, src/main.py</files>
  <action>
    **1. Bouton réinitialisation workflow (web)**

    Dans `workflow/index.html` :
    - Ajouter un bouton "Réinitialiser le workflow" dans la page workflow, visible quand il y a des résultats en DB (pending_validations > 0)
    - Style discret (comme le bouton suppression : rouge sombre)
    - Dialogue de confirmation overlay (pattern existant avec les dialogues custom overlay, voir `validation/list.html` pour le pattern)
    - Le bouton envoie `POST /workflow/reset`

    Dans `workflow.py` :
    - Ajouter une route `POST /workflow/reset` qui :
      a. Supprime toutes les `PendingValidationModel` via session.exec(delete(PendingValidationModel))
      b. Supprime toutes les `VideoFileModel` via session.exec(delete(VideoFileModel))
      c. Redirige vers `/workflow/` avec un message de confirmation
    - Ajouter le compteur `pending_count` au template context dans `GET /workflow/` pour conditionner l'affichage du bouton

    **Points d'attention :**
    - Utiliser `from sqlmodel import delete` pour le bulk delete (pas d'itération)
    - Sécurité localhost seulement (comme suppression bibliothèque) si applicable — mais le workflow est local par nature, donc pas nécessaire
    - Commit la session après les deux deletes

    **2. Logs serveur avec horodatage (main.py)**

    Dans la commande `serve` de `main.py` :
    - Configurer uvicorn pour utiliser loguru au lieu de son logger par défaut
    - Passer `log_config=None` à `uvicorn.run()` pour désactiver le logging par défaut d'uvicorn
    - Ajouter l'interception des logs uvicorn via loguru :
      ```python
      import logging

      class InterceptHandler(logging.Handler):
          def emit(self, record):
              level = logger.level(record.levelname).name
              logger.opt(depth=6, exception=record.exc_info).log(level, record.getMessage())

      logging.getLogger("uvicorn").handlers = [InterceptHandler()]
      logging.getLogger("uvicorn.access").handlers = [InterceptHandler()]
      ```
    - Ainsi les logs uvicorn passent par loguru et héritent du format avec timestamp
  </action>
