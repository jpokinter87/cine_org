<objective>
## Goal
Intégrer la détection de doublons pré-transfert avec comparaison qualité et sandbox dans le flux de transfert (CLI et web).

## Purpose
Avant chaque transfert, détecter si un titre similaire existe déjà (séries ET films) et présenter une comparaison avec métadonnées techniques et scores de qualité. L'utilisateur choisit : garder ancien / garder nouveau / garder les deux (ancien → sandbox). Résout le bug Gomorra (duplication répertoire).

## Output
- Service `DuplicateDetector` centralisé pour la détection pré-transfert
- Détection câblée dans `build_transfers_batch` (CLI) et `_run_web_transfer` (web)
- Comparaison avec scores qualité (réutilise `QualityScorerService`)
- "Garder les deux" utilise la sandbox au lieu de renommer en "(2)"
- Dialogue web de conflit enrichi avec scores qualité et recommandation
- CLI : tableau Rich enrichi avec scores
</objective>

<task type="auto">
  <name>Task 1: Créer DuplicateDetector service</name>
  <files>src/services/duplicate_detector.py, tests/unit/services/test_duplicate_detector.py</files>
  <action>
    Créer un service `DuplicateDetector` qui centralise la détection de doublons pré-transfert :

    1. **`detect_duplicate(title, year, video_dir, is_series) -> DuplicateMatch | None`**
       - Réutiliser la logique de `TransfererService.find_similar_content()` mais sur la racine video_dir (Films/ ou Series/)
       - Pour les films : chercher dans video_dir/Films/ par fuzzy matching sur titre normalisé
       - Pour les séries : chercher dans video_dir/Series/ récursivement dans les sous-dossiers de lettres
       - Seuil fuzzy : 0.85 (cohérent avec le reste du projet)
       - Retourne un `DuplicateMatch` dataclass avec : existing_dir, existing_title, existing_files_info, quality_score_existing

    2. **`compare_quality(existing_files, new_file_path) -> QualityComparison`**
       - Utiliser `QualityScorerService` pour calculer les scores des deux versions
       - Pour les séries : agréger le score de l'épisode équivalent (même SxxExx) ou moyenne
       - Retourner `QualityComparison` avec : existing_score, new_score, recommended ("new"|"old"), breakdown

    3. **`DuplicateMatch` dataclass** avec :
       - existing_dir: Path
       - existing_title: str
       - existing_files: list[ExistingFileInfo]  (réutiliser de transferer.py)
       - quality_existing: QualityScore
       - quality_new: QualityScore
       - recommended: str  ("new" ou "old")

    4. **Tests TDD** :
       - test_detect_duplicate_exact_match (même titre)
       - test_detect_duplicate_year_mismatch (Gomorra vs Gomorra (2014))
       - test_detect_duplicate_no_match
       - test_compare_quality_new_better (1080p HEVC > 720p H264)
       - test_compare_quality_old_better

    Ne PAS modifier `TransfererService.find_similar_content()` — le nouveau service le complète.
    Réutiliser `_normalize_title` et `_extract_title_year` depuis TransfererService (les importer ou les factoriser).
  </action>
  <verify>uv run pytest tests/unit/services/test_duplicate_detector.py -v</verify>
  <done>AC-1, AC-2, AC-3 satisfaits : détection et scoring fonctionnels</done>
</task>

<task type="auto">
  <name>Task 2: Intégrer la détection dans build_transfers_batch (CLI + web)</name>
  <files>src/adapters/cli/batch_builder.py, src/web/routes/transfer.py, src/services/transferer.py</files>
  <action>
    1. **Dans `build_transfers_batch`** (src/adapters/cli/batch_builder.py) :
       - Après avoir construit chaque `transfer_data` dict, appeler `DuplicateDetector.detect_duplicate()`
       - Si doublon détecté, ajouter les clés au dict de transfert :
         - `"duplicate_match"`: le DuplicateMatch
         - `"has_duplicate"`: True
       - Les fichiers sans doublon gardent `"has_duplicate": False`

    2. **Dans `_run_web_transfer`** (src/web/routes/transfer.py) :
       - Avant `check_conflict`, vérifier `transfer.get("has_duplicate")`
       - Si True, utiliser les données de `duplicate_match` pour peupler `conflict_data` avec les scores qualité
       - Ajouter les champs dans `conflict_data` :
         - `quality_existing`: score total + breakdown
         - `quality_new`: score total + breakdown
         - `recommended`: "new" ou "old"
         - `existing_episode_count` (pour séries)
       - Le conflit "similar_content" existant fusionne avec ce mécanisme

    3. **Modifier "keep_both"** dans `_run_web_transfer` :
       - Au lieu de renommer en "(2)", déplacer l'ancien vers sandbox via `move_to_staging()`
       - Utiliser un dossier sandbox dédié (config `sandbox_dir` ou fallback `/tmp/cineorg_sandbox`)
       - Le nouveau est transféré normalement à l'emplacement d'origine

    4. **Modifier "keep_new"** pour aussi utiliser la sandbox au lieu de trash_dir

    Ne PAS modifier le flux des conflits hash existants (DUPLICATE, NAME_COLLISION) — seulement ajouter la couche "similar content" en amont.
  </action>
