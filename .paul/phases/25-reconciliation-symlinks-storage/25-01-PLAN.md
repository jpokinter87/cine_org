<objective>
## Goal
Améliorer la réconciliation symlinks/storage pour résoudre les cas où les arborescences video/ et storage/ ont divergé (subdivision, année, genre différents), et mettre à jour les symlinks épisodes pour refléter les titres enrichis TVDB.

## Purpose
Actuellement, ~197 films sont considérés "sans fichier" et de nombreux symlinks sont cassés parce que l'algorithme de recherche ne regarde que 2 niveaux au-dessus du target original. Quand la structure a changé (regroupement, re-subdivision, changement de genre), le fichier physique n'est pas retrouvé. La réconciliation basée sur les métadonnées DB résoudra la majorité de ces cas.

## Output
- RepairService enrichi avec recherche basée métadonnées DB (Movie/Series → fichier physique via scan storage)
- Commande CLI `reconcile` qui orchestre la réconciliation complète
- Mise à jour des symlinks épisodes avec les titres TVDB enrichis
</objective>

## AC-1: Recherche métadonnées pour symlinks cassés films
```gherkin
Given un symlink cassé dans video/Films/ dont le target original n'existe plus
When le RepairService cherche des candidats
Then il consulte la DB pour trouver le MovieModel correspondant (par titre normalisé)
And il cherche le fichier physique dans tout storage/Films/ (pas juste parent/grandparent)
And il retourne le fichier trouvé avec un score élevé
```

## AC-2: Recherche métadonnées pour symlinks cassés séries
```gherkin
Given un symlink cassé dans video/Séries/ dont le target original n'existe plus
When le RepairService cherche des candidats
Then il consulte la DB pour trouver l'EpisodeModel correspondant (par titre série + SxxExx)
And il cherche le fichier physique dans storage/Séries/ en parcourant les sous-répertoires
And il retourne le fichier trouvé avec un score élevé
```

## AC-3: Mise à jour file_path DB quand le fichier est retrouvé ailleurs
```gherkin
Given un MovieModel/EpisodeModel dont le file_path pointe vers un chemin inexistant
When la réconciliation retrouve le fichier physique à un autre emplacement
Then le file_path dans la DB est mis à jour vers le nouveau chemin
And le symlink est recréé vers le bon target
```

## AC-4: Commande CLI reconcile
```gherkin
Given l'utilisateur lance `cineorg reconcile`
When la commande s'exécute
Then elle affiche un rapport avec :
  - Nombre de symlinks cassés trouvés
  - Nombre réconciliés via métadonnées DB
  - Nombre réconciliés via recherche large storage
  - Nombre restants non résolus
And les corrections sont appliquées automatiquement (file_path + symlinks)
```

## AC-5: Mise à jour symlinks épisodes avec titres TVDB

  <action>
    Ajouter une nouvelle méthode `_find_by_metadata(link: Path) -> list[tuple[Path, float]]` dans RepairService :

    1. **Extraction du titre depuis le nom du symlink** : utiliser `extract_clean_title()` et `extract_series_info()` existants pour identifier le titre, l'année, et si c'est un épisode (SxxExx)

    2. **Recherche DB pour les films** :
       - Requête `MovieModel` par titre normalisé (LIKE %titre%) avec tolérance accents/articles
       - Si trouvé et `movie.file_path` existe sur disque → retourner directement (score 100)
       - Si trouvé mais `file_path` inexistant → chercher dans tout `storage/Films/` via `rglob()` avec le nom du fichier (pas le chemin complet)
       - Utiliser `extract_clean_title()` pour comparer les candidats trouvés

    3. **Recherche DB pour les séries** :
       - Extraire titre série + saison + épisode depuis le nom du symlink
       - Requête `SeriesModel` par titre normalisé
       - Puis requête `EpisodeModel` par series_id + season + episode
       - Si trouvé et `episode.file_path` existe → retourner (score 100)
       - Si trouvé mais inexistant → chercher dans `storage/Séries/` via rglob

    4. **Intégrer dans `find_possible_targets()`** :
       - Appeler `_find_by_metadata()` EN PREMIER (avant _find_regroup_candidates et _search_in_directory)
       - Si résultat trouvé avec score >= 90 → retourner sans chercher plus loin
       - Sinon combiner avec les résultats existants

    **Points d'attention :**
    - La session DB doit être passée via le container DI (le RepairService a accès au container)
    - Ne PAS modifier la signature publique de `find_possible_targets()`
    - Limiter le rglob à `storage/Films/` ou `storage/Séries/` selon le type détecté
    - Le rglob peut être lent : construire un index une seule fois et le réutiliser (pattern existant `build_file_index`)
  </action>
