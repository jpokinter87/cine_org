<objective>
## Goal
Améliorer deux irritants UX quotidiens sur les champs texte :
1. Un bouton ✕ réutilisable d'effacement instantané du contenu, appliqué en
   priorité au champ de recherche bibliothèque et à l'input URL de l'overlay
   d'édition métadonnées.
2. Le debounce de la recherche bibliothèque, actuellement trop court, fait
   perdre le focus en pleine frappe et coupe la saisie : augmenter le delay
   et préserver le focus lors du swap HTMX.

## Purpose
Lever deux frictions signalées pendant la vérification de la phase 42-02 /
43-01 : effacer une recherche demande actuellement de tout sélectionner puis
supprimer, et une petite faute de frappe relance la query avant que
l'utilisateur ait fini de taper, redirigeant la page et perdant le focus.

## Output
- Script JS global `static/js/input_clear.js` chargé dans `base.html` qui
  attache automatiquement un bouton ✕ à tout input ayant l'attribut
  `data-clearable` (ou classe `.input-clearable`).
- CSS dédié pour le bouton et le wrapper `.input-clearable-wrap`.
- Input de recherche bibliothèque (`_filters.html`) équipé du wrapper +
  `data-clearable` + `hx-preserve="true"` pour conserver le focus au swap.
- Delay debounce du trigger HTMX de recherche passé de `700ms` à `1000ms`.
- Input URL de l'overlay d'édition métadonnées équipé du wrapper +
  `data-clearable`.
- Aucun impact sur les autres surfaces (CLI, workflow, config — reportés
  si besoin).
</objective>

## AC-1: Bouton ✕ réutilisable via data-clearable
```gherkin
Given un `<input type="text" data-clearable value="abc">` dans le DOM
When la page est chargée (DOMContentLoaded) OU l'input est injecté
    dynamiquement par HTMX (via event htmx:afterSwap)
Then un bouton `.input-clear-btn` (✕) apparaît superposé à droite de l'input
And le bouton est visible uniquement quand `input.value` est non-vide
And un clic sur le bouton :
    - vide l'input (value = "")
    - replace le focus dans l'input
    - dispatche un event `input` bubblable (déclenche HTMX si configuré)
    - cache le bouton (puisque value redevient vide)
```

## AC-2: Recherche bibliothèque avec bouton ✕ + debounce 1000ms + focus préservé
```gherkin
Given la page /library/?q=Millénium (champ pré-rempli)
When l'utilisateur voit le champ de recherche
Then un bouton ✕ est visible à droite du champ
And le delay HTMX `keyup changed delay:1000ms from:find input[name=q]` est
    appliqué (vs 700ms avant)
When l'utilisateur tape rapidement puis fait une pause
Then le focus reste dans le champ après le swap HTMX (grâce à hx-preserve
    + form extérieur à #library-content)
When l'utilisateur clique le bouton ✕
Then le champ se vide, le focus reste, et la recherche se relance avec q=""
    (retour à la liste complète)
```

<task type="auto">
  <name>Task 1 — Script JS + CSS réutilisables pour bouton d'effacement</name>
  <files>
    src/web/static/js/input_clear.js,
    src/web/templates/base.html,
    src/web/static/css/style.css
  </files>
  <action>
    **1a. Créer `src/web/static/js/input_clear.js`** :

    Module IIFE auto-initialisé qui :
    - Sélectionne `input[data-clearable]` au DOMContentLoaded et après
      chaque `htmx:afterSwap` global (pour couvrir les inputs injectés).
    - Pour chaque input : si son parent direct n'a pas la classe
      `.input-clearable-wrap`, enveloppe l'input dans un
      `<span class="input-clearable-wrap">` et insère un
      `<button type="button" class="input-clear-btn" aria-label="Effacer">✕</button>`.
    - Attache listeners :
      - `input` / `change` : met à jour la visibilité du bouton via
        classe `.has-value` sur le wrap (CSS gère le display).
      - `click` sur le bouton :
        - `e.preventDefault(); e.stopPropagation();` (ne pas remonter au
          form)
        - `input.value = ""`
        - `input.focus()`
        - dispatch `new Event("input", { bubbles: true })` puis
          `new Event("change", { bubbles: true })` — déclenche HTMX
        - met à jour `.has-value` (off)
    - Exportable : fonction `attachClearButton(input)` réutilisable.
    - Ne pas double-attacher si `input.dataset.clearAttached === "1"`.

    **1b. Inclure le script dans `base.html`** :

    Après le chargement de HTMX, ajouter :
    ```html
    <script src="/static/js/input_clear.js?v={{ asset_version() }}"></script>
    ```

    **1c. CSS `.input-clearable-wrap` + `.input-clear-btn`** (dans
    `style.css`, à la fin du fichier) :
    - `.input-clearable-wrap` : `position: relative; display: inline-flex;
      align-items: center; width: 100%;` (ou 100% si wrappe l'input)
    - `.input-clearable-wrap input` : `padding-right: 2rem;` (ménager
      l'espace pour le bouton)
    - `.input-clear-btn` :
      - `position: absolute; right: 0.5rem; top: 50%;
        transform: translateY(-50%);`
      - `width: 1.25rem; height: 1.25rem; border-radius: 50%;`
      - `background: transparent; border: none; cursor: pointer;`
      - `color: var(--text-muted); font-size: 0.75rem;`
      - `display: none;` par défaut, `display: inline-flex;` quand
        parent `.has-value`
      - `:hover` → `color: var(--accent-rose); background: var(--accent-rose-dim);`
      - Accessibilité : `:focus-visible` outline amber
    - Transitions douces sur `color` et `background`.
    - Pas d'impact sur le layout des inputs sans `data-clearable`.

    **Attention** : `.lib-search-wrap` contient déjà l'input de recherche
    avec une icône loupe. Il faut que le bouton ✕ cohabite avec la loupe
    sans conflit. Le script JS peut détecter la présence d'un wrap
    existant et injecter uniquement le bouton (pas le wrapper). Ajouter
    donc une deuxième branche : si l'input est déjà dans un parent dont
    `position: relative`, ne pas créer de nouveau wrap, juste injecter
    le bouton dans ce parent.
  </action>
